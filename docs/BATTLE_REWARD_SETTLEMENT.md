# V0.4 战斗奖励结算与恢复语义

任务：QYS-V04-004。状态：已编码与测试，待负责人验收。

## 结算标识

- 每次成功开始战斗都会分配一个单调递增的 `battle_encounter_sequence`。
- 当前场次记录为 `active_battle_encounter_id`；最近成功结算记录为 `last_settled_battle_encounter_id`。
- 只有“仍在战斗、ID 等于当前场次、ID 大于最近结算”的请求可以进入胜利结算。
- 胜利入口一次性处理三资源、胜场、关卡解锁、战斗停止和重复等待。重复调用、停止后调用、失败后调用以及读取已结算存档后再次调用都会被拒绝。
- 奖励仅接受现有 `wood`、`spirit_stone`、`food`，数值仍来自 `BattleCatalog`；本任务不增加奖励种类或调整关卡数值。

## 保存与异常中断

- 场次序号、当前场次和最近结算 ID 随游戏状态保存。完成结算后自动保存；保存成功才显示“已保存”。
- 保存失败会通过既有 `save_completed(false, ...)` 显示明确错误，不能显示为已经持久化。内存中的本场结果仍保留，后续成功保存可将其持久化。
- 若异常中断发生在结算后、成功保存前，磁盘仍是结算前状态；重新读取后会恢复该场战斗，并只允许再次结算一次。这可能重演尚未持久化的一场，但不会在同一份持久化状态上叠加两次奖励。
- 当前 `FileAccess.WRITE` 的安全写入、备份与失败回滚仍由 QYS-V04-005 完成。本任务不声称已经解决文件写入中断导致的损坏。

## V0.3 兼容

- 新存档包含三个场次跟踪字段，外层 `SAVE_VERSION` 仍为 1。
- V0.3 存档没有这些字段：若保存于战斗中，读取时分配一个新的有效场次 ID；若处于停止或胜利等待，则保持无活动场次。
- 新字段只出现一部分、最近结算号超过总序号、或活动场次号越界时拒绝读取，避免含糊恢复。

专项测试覆盖单次胜利、重复结算、失败与停止不发奖、保存失败提示、结算前存档恢复、结算后存档恢复和 V0.3 缺字段恢复。
