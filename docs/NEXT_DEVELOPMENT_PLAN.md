# 《青云宗》后续开发计划

更新日期：2026-10-22。本文只记录版本级执行顺序；具体任务状态以GitHub Issues和负责人验收记录为准。

## 当前阶段：V0.8验收与归档

1. 负责人使用本机`builds/QingYunSect-v0.8-sync15-win64.exe`（候选14游戏内容）在1280×720与1920×1080下完成固定主殿+七功能院落、付费建设、实例管理、施工/升级反馈、轮廓选中、模块开关和旧存档手工验收。单位电脑原候选14仍可对照，overlay旧包为历史记录。
2. 若发现问题，只修复V0.8美术、UI、可读性和兼容性范围内的缺陷，重新执行48组回归并更新候选包。
3. 只有负责人明确确认后，才把GitHub Issues #36～#42标记为ACCEPTED并关闭，创建`v0.8.0`标签并归档V0.8。
4. V0.8验收前不进入V0.9功能编码，不修改V0.7数值、12×8地图契约或version 3存档结构。

## 下一阶段：V0.9单人肉鸽战斗原型

V0.9先做设计冻结与技术原型，待负责人批准拆分Issue后再编码。计划目标：

- 将宗门经营场景与可主动操作的俯视角战斗场景解耦，保持现有经营存档可继续读取。
- 建立单角色移动、朝向、普通攻击、技能、受击、死亡及基础敌人行为的最小闭环。
- 建立可重复进入的房间流程、基础随机内容和一次完整关卡的成功/失败结算。
- 将肉鸽奖励通过统一结算入口安全回流宗门，失败、重复结算和读档不得重复发奖。
- 优先复用V0.8已确定的半写实国风、图标和信息层级，不在原型期一次性扩充大量角色、敌人或联机内容。

## 后续版本边界

- V0.10：在V0.9原型通过验收后扩展为单人肉鸽完整闭环。
- V0.11～V0.13：按技术验证、双人合作、四人合作顺序推进；联机必须单独批准，不能提前混入单人原型。
- V0.14：补齐正式内容与肉鸽、职业、怪物、联机美术，不推翻V0.8宗门视觉基线。
- V0.15：功能、存档、性能、联机和Windows发布测试。
- V1.0：完成单人宗门经营与最多四人合作肉鸽的完整Windows交付。

## 下一次开工前的决策点

V0.8正式验收后，先提交V0.9的范围、核心操作、单局时长、首批角色/敌人数量、奖励回流规则和验收标准供负责人确认；未确认前只做规划，不自动开始实现。
