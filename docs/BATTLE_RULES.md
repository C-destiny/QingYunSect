# V0.4 自动战斗规则契约

任务：QYS-V04-002、QYS-V04-003 已验收；奖励结算补充：QYS-V04-004 已编码与测试，待负责人验收。

本契约整理 V0.3 已有规则并明确边界，不调整数值，不改变存档结构。数值唯一来源为 `scripts/data/battle_catalog.gd`；`GameState` 负责状态与结算，UI 只展示和发出操作。

## 属性和伤害

炼气层数记为 `r`，最小按 1 计算：

- 生命：`100 + 20 × (r - 1)`。
- 攻击：`10 + 3 × (r - 1)`。
- 防御：`5 + 2 × (r - 1)`。
- 队伍生命、攻击、防御分别为参战成员对应属性之和。
- 单次伤害：`max(1, 攻击 - 防御)`。

以上公式、每回合 1 秒、胜利后等待 2 秒均集中在 `BattleCatalog`。五关敌人属性与奖励保持 V0.3 数值。

## 状态转换

当前对外可观察状态：

```text
stopped ──有效开战──> fighting
fighting ──胜利且自动开启──> repeat_wait
repeat_wait ──等待结束且队伍有效──> fighting
fighting ──失败/手动停止/实际队伍变动──> stopped
repeat_wait ──手动停止/实际队伍变动/队伍异常──> stopped
```

- 开战要求队伍非空、关卡存在且已解锁。
- 战斗中再次请求开战返回失败，不能重置双方生命、回合进度或重复创建战斗。
- 战斗中不能切换关卡。
- 手动停止清除自动重复和等待时间，不发奖励。
- 无效或非正数 `delta` 不推进状态。
- 每次 `process_battle(delta)` 最多完成当前一场战斗。若一个大 `delta` 足以结束本场，胜利后的重复等待从下一次调用开始；剩余时间不跨场折算，避免一帧内连续结算多场奖励。
- 我方先攻击；敌方被击败后本回合不再反击。失败后自动重复关闭。

## 队伍与岗位一致性

- `battle_party` 必须与所有 `combat` 岗位弟子的 ID 集合完全一致，最多三人且不允许重复或缺失 ID。
- 满队时拒绝新成员，原岗位与现有队伍保持不变；重复设置相同岗位是无副作用的成功操作。
- 非战斗岗位之间调动不会停止战斗；加入或离开战斗队伍会在战斗中或胜利等待期立即停止自动循环。
- 战斗推进前再次校验队伍。空队、缺失成员或集合不一致会安全停止，且不会结算奖励。

## 战斗中的属性变化

- 开战时确定队伍最大生命和当前生命，本场不会因中途突破补充或提高生命上限。
- 攻击和防御在每回合开始时根据当前成员境界重新计算；战斗中突破从下一回合影响攻击和防御。
- 这是 V0.3 行为的明确化。若以后改为整场属性快照，属于战斗规则变更，需负责人批准并评估存档迁移。

## 本任务边界

QYS-V04-002 只集中公式、暴露状态读法、防止战斗中重复开战并固定时间推进契约。QYS-V04-003 补齐队伍异常和等待期队伍变动；奖励幂等和存档事务分别由 QYS-V04-004、005 处理。

QYS-V04-004使用持久化场次ID保护胜利结算，具体异常中断与恢复边界见 `docs/BATTLE_REWARD_SETTLEMENT.md`。

专项测试覆盖各层属性、最小伤害、重复开战、非正时间、大时间步、状态转换、我方先手、战斗中突破，以及满队、同岗位、无关调岗、等待期空队、缺失 ID 和读档集合一致性。
