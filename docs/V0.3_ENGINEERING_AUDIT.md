## 模块与依赖

- scripts/core/game_state.gd：经营库存、招募、岗位、弟子成长、建筑升级、宗门等级、战斗状态与结算，负责导入导出数据。
- scripts/core/save_manager.gd：读取/写入JSON，调用GameState；通过信号通知保存和读取结果。
- scripts/data/building_catalog.gd：五类建筑配置、升级成本和时间公式。
- scripts/data/battle_catalog.gd：三人上限、五关敌人属性和奖励配置。
- scripts/world/sect_map.gd：地图绘制、资源点配置、放置交互；通过信号告知UI选择或建造请求。
- scripts/main/main.gd：调用状态API、刷新界面、每帧驱动生产/施工/招募/消耗/修炼/战斗；胜利后调用保存。
- scenes/main/main.tscn：主界面、侧栏、计时器。

数据和UI已有基本分离，但计时调度在主UI脚本，资源生产基础速率在地图脚本；GameState同时承担多个系统。现状不要求整体重构，只对已批准的V0.4问题局部调整。
战斗使用队伍汇总生命池，不存在逐成员当前生命或死亡状态。V0.4成员展示不能凭空声称单体HP已实现。

## 当前规则（代码事实，未改数值）

- 弟子层数r：HP=100+20(r−1)，攻击=10+3(r−1)，防御=5+2(r−1)，队伍三项均求和。
- 每秒结算一回合，我方先手；伤害=max(1,攻击−对方防御)。敌人生命归零后不反击。
- 开战满血；胜利进入2秒等待后重复当前关卡；失败停战；停止不发奖励。
- 回合内重新读取队伍攻击和防御；最大生命在开战时确定。战斗中突破的属性取样需要明确定义。
- 战斗胜利在_complete_battle_victory直接修改resources、胜场、解锁和重复等待，再发resources_changed；主UI收到process_battle的true后保存。
- 当前结算没有持久的battle_id/已结算标记，不具备入口幂等保证。
- get_site_workforce_power只计对应采集岗位，process_training只计training；set_disciple_job入队时将job改为combat并加入battle_party。
- 生产基础速率：木材12/人/分、灵石8、灵谷10；境界每高一层+5%，建筑及宗门另乘，缺粮×0.5，每弟子消耗1灵谷/分。
- 五关、三资源、五建筑、宗门1～5级及炼气1～9层保持现状。
